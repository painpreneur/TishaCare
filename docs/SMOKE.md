# Смоук-чеклист приёмки

Ручная проверка перед выкаткой в прод (после того, как CI зелёный и ветка
задеплоена). ~15 минут. Прогонять на **staging**-контуре, а пока его нет — на
локальном контуре с dev-ботом (см. [ENVIRONMENTS.md](ENVIRONMENTS.md)).

## Бот и онбординг

- [ ] `/start` у бота контура → приветствие с кнопкой «Открыть приложение»
- [ ] повторный `/start` → «С возвращением», без дубля пациента
- [ ] кнопка открывает Mini App внутри Telegram, не в браузере
- [ ] новый пациент → админу приходит уведомление (если задан `ADMIN_TELEGRAM_ID`)
- [ ] `/checkin` в боте: мастер с клавиатуры (настроение → теги/сон → …), в конце
      «Готово, отметка сохранена ✅» и разбор ответов второй строкой

## Mini App (пациент)

- [ ] первый вход без даты рождения → онбординг профиля; вводится **полная дата**
- [ ] чек-ин: пошаговый мастер, переходы слайдом, экран «Готово, я записал ваши
      ответы» с разбором; повторный заход показывает историю за сегодня
- [ ] чек-ин с настроением ≤ −1 → на финальном экране ссылка «план на трудный момент»
- [ ] «Моя динамика»: блок «Как читать график» (раскрыт при первом заходе),
      график настроения/сна/приёма, переключатель 7/30/90 дней
- [ ] опросники: Бек, MDQ, GAD-7, ASRS, AQ-10, MSI-BPD, **PHQ-9**, **YMRS** —
      каждый проходится и показывает интерпретацию с дисклеймером
- [ ] когнитивный тест: 9 субтестов открываются, результат сохраняется
- [ ] колесо баланса проходится, есть в «Моей динамике»
- [ ] «Открытия»: экран открывается, разблокировки соответствуют пройденному
- [ ] медикаменты: при подключённом враче список ведёт врач (пациент отмечает
      только переносимость); без врача — можно добавить через справочник
- [ ] дневник мыслей: запись сохраняется, редактируется, удаляется
- [ ] «План на трудный момент»: пусто → «Заполнить», сохранение, просмотр,
      блок срочной помощи (103/112, 8-800-2000-122) виден всегда
- [ ] профиль: тумблер «Напоминать о чек-ине в боте» переключается и сохраняется

## Веб-панель (врач)

- [ ] логин демо-доступом, редирект на `/dashboard`
- [ ] блок «Требуют внимания»: флагнутые пациенты с причинами, сортировка по
      давности последнего сигнала; остальные ниже
- [ ] блок «Ближайшие приёмы»: запланированные приёмы, просроченные помечены
- [ ] карточка пациента: график самочувствия, баллы всех опросников, «Динамика
      по шкалам» включает PHQ-9 и YMRS, когнитивные категории
- [ ] карточка: «Запланировать приём» (дата в будущем) → в блоке «Запланировано»;
      «Отметить состоявшимся» переносит его в историю
- [ ] редактирование анамнеза сохраняется
- [ ] «Подключить пациента» по коду приглашения работает
- [ ] пациент с PHQ-9, где отмечен пункт 9 → флаг «мысли о самоповреждении»
- [ ] логаут → редирект на `/login`, `/dashboard` больше не открывается

### Регистрация врача (`/register`)

- [ ] «Работаю в клинике» + название → создаётся клиника, врач админ, в topbar её название
- [ ] «Самозанятый» → врач без клиники, в topbar «Частная практика»
- [ ] повторная регистрация на тот же email → ошибка, клиника-сирота не создаётся
- [ ] короткий пароль / кривой email / клиника без названия → понятная ошибка

### Управление клиникой (`/dashboard/clinic`, только админ)

- [ ] врач-member по прямой ссылке `/dashboard/clinic` → редирект на `/dashboard`
- [ ] создать ссылку-приглашение → регистрация по ней (`/register?clinic_invite=…`)
      заводит врача в клинику как member, ссылка гаснет
- [ ] повторный переход по использованной ссылке → «уже использовано»
- [ ] повысить/понизить роль; последнего администратора понизить нельзя

### Гейт по лицензии

- [ ] `Clinic.licenseActive = false` → врач входит, сверху баннер, скрыты
      «Подключить пациента», формы приёмов/медикаментов, кнопка редактирования
      анамнеза; мутационные роуты отвечают `403`
- [ ] `licenseActive = true` → всё как обычно

## Веб-портал пациента (`/app`)

- [ ] `/app` без сессии → редирект на `/app/login`
- [ ] регистрация нового пациента → попадает в `/app`
- [ ] вход по email/паролю → онбординг (согласие → полная дата рождения) → меню
- [ ] неверный пароль 5 раз → блокировка на 15 мин (даже с верным паролем — `429`)
- [ ] чек-ин / «Моя динамика» / опросники / «План на трудный момент» на `/app/*` работают
- [ ] Telegram-пациент в профиле Mini App задаёт email+пароль и входит на `/app`
- [ ] логаут в `/app` → редирект на `/app/login`

## Напоминания и бот-нуджи

- [ ] ручной вызов `/api/cron/reminders` с `Authorization: Bearer $CRON_SECRET` →
      `{ ok: true, checkins, medReminders, encounters, reengagement }`
- [ ] без заголовка / с неверным секретом → `401`
- [ ] пациенту без чек-ина сегодня приходит напоминание; отметившемуся — нет
- [ ] пациент с выключенным тумблером напоминаний — не получает
- [ ] запланированный приём на завтра → пациенту приходит напоминание за день
- [ ] пациент без чек-инов ≥ 3 дней → одно тёплое сообщение ре-энгейджмента,
      ежедневное напоминание ему при этом не дублируется

## Контур

- [ ] на проде `MINIAPP_DEV_BYPASS` не задан (иначе деплой падает — это ожидаемо)
- [ ] `WEBAPP_URL` в кнопке бота ведёт на этот же контур
