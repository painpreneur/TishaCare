# TishaCare

Цифровая платформа мониторинга пациентов с БАР (по мотивам ВКР). Пациент ведёт
короткие ежедневные записи о состоянии, врач видит динамику между визитами.

## Из чего состоит

- **apps/web** — Next.js. Три поверхности в одном деплое:
  - `/dashboard` — панель врача: список пациентов с блоком «Требуют внимания»,
    карточка пациента (график самочувствия, опросники, медикаменты, приёмы,
    анамнез, дневник мыслей), приёмы и их планирование, управление клиникой и
    приглашение коллег.
  - `/miniapp` — Telegram Mini App для пациента (авторизация через `initData`).
  - `/app` — тот же функционал пациента в вебе, вход по email/паролю.
  - `/api/bot/webhook` — приём апдейтов боевого бота; `/api/cron/*` — Vercel Cron.
- **apps/bot** — локальный dev-бот на long-polling. Продакшен обслуживает вебхук
  внутри `apps/web`, этот процесс не деплоится (см. docs/ENVIRONMENTS.md).
- **packages/bot-core** — вся логика бота (`createBot`, чек-ин с клавиатуры,
  напоминания, меню). Оба входа (`apps/web/lib/bot.ts`, `apps/bot/index.ts`)
  только вызывают её и различаются транспортом.
- **packages/db** — Prisma-схема и клинический контент (тексты и подсчёт баллов
  опросников, когнитивная батарея, справочник препаратов), общий для всех.

## Что умеет

Пациент:

- **Чек-ин** — пошаговый мастер: настроение, состояние, энергия, сон, приём
  препаратов. Доступен и в Mini App, и полностью с клавиатуры бота (`/checkin`).
- **«Моя динамика»** — график по своим отметкам, с пояснением как его читать.
- **Опросники** — Бек, MDQ, GAD-7, ASRS, AQ-10, MSI-BPD, PHQ-9, YMRS, колесо
  баланса, когнитивная батарея из 9 субтестов. Результат с интерпретацией и
  дисклеймером; пороги — эвристические, MVP-уровня, не валидированы специалистом.
- **Дневник мыслей**, **медикаменты** (при подключённом враче список ведёт врач),
  **«Открытия»** (прогресс «Плотина Тиши» за сам факт регулярных записей),
  **«План на трудный момент»** (кризисный план + телефоны помощи).

Врач:

- Дашборд-триаж: кто давно не отмечался, просадка настроения, пропуски приёма,
  плохая переносимость, положительный MDQ, отметка о самоповреждении в PHQ-9 —
  каждый флаг говорит, почему пациент в списке.
- Карточка пациента, приёмы и планирование приёмов (напоминание пациенту за день),
  экспорт карты, отвязка пациента.
- Регистрация клиники или частной практики, роли admin/member, одноразовые
  ссылки-приглашения коллегам, гейт по лицензии клиники (read-only при отключении).

Бот-нуджи: ежедневное напоминание о чек-ине (отключаемо в профиле), напоминание
о завтрашнем приёме, мягкий ре-энгейджмент при долгом молчании.

## Установка (локально)

```bash
npm install
createdb tishacare            # brew install postgresql@14, если ещё нет
cp apps/web/.env.example  apps/web/.env.local
cp apps/bot/.env.example  apps/bot/.env
cp packages/db/.env.example packages/db/.env
# впишите DATABASE_URL / DIRECT_URL (локальный PG) и TELEGRAM_BOT_TOKEN (@…_dev_bot)
npm run db:migrate:deploy
npm run db:seed
```

Сид создаёт демо-клинику, трёх врачей (`doctor@demo.local` — админ,
`member@demo.local`, `solo@demo.local`, пароль у всех `demo1234`), веб-пациента
(`patient@demo.local` / `demo1234`) и двух подключённых пациентов с историей.

Схема БД — только через версионированные миграции, см. [docs/DATABASE.md](docs/DATABASE.md).

## Запуск

```bash
npm run web    # http://localhost:3000
npm run bot    # long-polling dev-бот
```

Для Mini App на телефоне нужен HTTPS-туннель (ngrok / cloudflared), его адрес в
`WEBAPP_URL`. В Telegram: `/start` у dev-бота, дальше по кнопке в Mini App.

## Происхождение

Часть клинического контента портирована из более раннего прототипа на
python-telegram-bot (2024): тексты и логика Бека и MDQ, учёт медикаментов,
дневник мыслей. MDQ здесь считается по клиническим критериям (≥ 7 «да» +
совпадение по времени + умеренное/серьёзное влияние), а не простой суммой.

⚠️ В архиве того прототипа были закоммичены реальные Telegram-токен и OpenAI-ключ.
В этот репозиторий они не переносились — если ещё не сделали, отзовите их.
